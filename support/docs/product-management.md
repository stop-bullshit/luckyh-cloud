# 商品管理

## 使用方式

前端“业务管理 → 商品管理”（`/business/products`）展示库存服务中的商品，支持名称搜索、分页、新增、编辑和补货。已有三个演示商品来自 `support/sql/03-distributed-demo.sql`，不会因升级而重置。

1. 新增商品时填写名称和单价，商品编号由数据库生成，初始库存为 0。
2. 在商品行点击“补货”，输入本次增加数量。
3. 购买演示和库存查询页面按名称搜索并选择商品，选项显示单价和库存。
4. 编辑商品只修改名称和单价；已有订单中的名称与成交价格快照不随之变更。

## 接口

以下路径均通过已有网关库存路由访问：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/inventory/inventory?current=1&size=10&productName=` | 商品分页和名称搜索，单页最多 100 条 |
| POST | `/api/inventory/inventory` | 新增，正文为 `productName`、`productPrice`，返回商品编号 |
| PUT | `/api/inventory/inventory/{productId}` | 编辑名称和单价 |
| POST | `/api/inventory/inventory/{productId}/replenish` | 补货，正文为正整数 `quantity` |
| GET | `/api/inventory/inventory/{productId}` | 读取单个商品和最新库存 |

商品名称最多 128 字符；单价范围为 0.01–99,999,999.99 元、最多两位小数，与订单金额字段容量一致。补货按增量在数据库中更新，并检查 INT 上限。编辑和补货在本地事务提交时检查 Seata 全局锁，避免撞上购买事务的回滚窗口；依据 [Seata 事务隔离说明](https://seata.apache.org/docs/user/appendix/isolation)。

新增和后续更新均由数据库生成更新时间，沿用库存表现有时间来源。

## 升级

库存表和库存服务继续复用，不新增商品表、服务或网关路由。新建环境执行新版 `03-distributed-demo.sql`；已有库存库执行 `04-product-management.sql` 后更新库存服务。详见 [数据库升级步骤](../sql/README.md)。
